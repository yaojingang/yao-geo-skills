# 浏览器采集规程

## 范围

- 每个目标词从百度首页开始，在当前浏览器会话里依次操作。
- 可用 `cua_repl` 时使用它操作页面；首次调用遵守工具文档的单一入口调用要求。选择用户指定的浏览器；用户未指定时可用应用内浏览器并保持后台状态。标签页接口不可用时，可用已打开浏览器的原生应用入口继续执行。
- 按页面实际 UI 查找输入框和按钮。百度首页可能采用新版输入框；以可访问性树和截图为准。
- 每次动作后重新观察页面，确认关键词、下拉词或搜索结果页已出现，再决定下一步。联想词可能因地区、登录状态、时间而变化。

## 下拉框

1. 打开 `https://www.baidu.com/`，清空输入框，输入完整目标词，暂不按回车。
2. 等待浏览器状态更新并查看截图。截图应同时包含输入词和完整下拉词列表。若列表超出视口，逐段截图，确保每条可读。
3. 从列表逐条读取页面可见文字，记录一到十等显示顺序。可访问性树将高亮片段分开时，结合页面文本和截图还原完整词条，保留有实际意义的空格。
4. 下拉框未出现时再聚焦输入框观察一次。仍未出现则记 `empty`；加载失败记 `error`；人机校验记 `blocked`。

## 结果页底部

1. 从已输入的页面提交搜索，确认搜索框仍为目标词，记录实际结果页 URL。
2. 滚动到第一页底部，寻找主结果区、分页栏上方的“相关搜索”。截图包含标题、全部词条及足够的周围页面，便于判断采集位置。
3. 页面可能另有侧栏“相关搜索”或正文“大家还在搜”。只读取页尾区块。若页尾区块跨多个视口，保存多张截图并分别记录。
4. 核对截图与读出的词条顺序和数量；无法确认的词条不猜测。

## 截图保存

每词各建 `001-autocomplete`、`001-bottom` 形式的证据文件，编号按目标词顺序排列。使用浏览器工具提供的真实截图字节；在 `cua_repl` 中可用 `await tab.getScreenshot({emit:false})` 或原生应用的 `await app.getScreenshot({emit:false})` 取得字节，并用 `await import('node:fs/promises')` 的 `writeFile` 保存。按实际图片格式选择 `.png` 或 `.jpg` 扩展名，保存后核对文件头或图片类型；截图接口可能返回 JPEG 字节。若工具提供专门的截图保存接口，按该接口操作。多张截图按 `001-bottom-2` 续号。

截图需清晰、完整、与 JSON 中的关键词和来源对应。截图文件保存到本次运行文件夹的 `evidence/`，JSON 里使用相对于该文件夹的路径。不要通过修改图片补造页面内容。

## 完成与异常

按目标词逐个完成，不并发打开大量搜索页。页面受阻时如实记录状态与说明；遇到验证码交由用户处理。汇总时说明缺失的区块和原因。截图只是采集时页面的证据，不能承诺百度会持续显示相同建议。
