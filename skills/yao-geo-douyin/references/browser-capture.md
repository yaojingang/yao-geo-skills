# 抖音网页版采集规程

## 首次进入与定位

- 优先接续用户指定的抖音网页及浏览器；没有可用页面时首次打开 [抖音网页版](https://www.douyin.com/)。2026-09-30实网页观察到首页自动跳转到 `/jingxuan`，顶部输入框提示“搜索你感兴趣的内容”。自动跳转是页面行为，记录最终URL；保持当前页进入采集循环。未来页面可能不同，重新观察定位。
- 在Codex中默认使用电脑操作能力控制已授权的Chrome窗口，通过原生UI定位、编辑输入、读取状态与截图。按可见输入框文字、角色与页面位置定位，每次读取新状态再确定控件；不写死坐标、AX索引或动态CSS类名。保持自然窗口尺寸。
- 固定本批次的浏览器和抖音标签页。每次输入前重新核对目标页面与输入焦点；用户切换页面或正在操作时暂停全局键盘输入，保存检查点。工具连接超时后先检查当前状态，不能假定上一步未执行而重复打开或输入。
- 搜索框被弹窗遮挡、网页登录失效或出现验证码时，交由用户在当前页面处理。不要循环刷新、切账号、换代理或调用内部接口。用户完成后接续检查点。
- 采集循环只允许工具提供的定位、聚焦、选中旧文字、替换输入、读取页面和截图。优先无点击的输入/聚焦能力或键盘Tab定位；工具必须点击才能触发时记 `error`，说明操作约束不满足。禁止在循环中点击搜索按钮、建议词、视频或页面链接；禁止提交回车、刷新、跳转、翻页。首次打开页面与用户手动登录在循环之前处理。

## 一个检索词的完成条件

1. 记录输入前实际页面URL。定位页面顶部搜索框，完整替换旧词，确认可见输入值与检索词完全一致。原生 `setValue` 若仅改变文字而未触发联想，可在已核对的输入框中改用真实键盘编辑，方法见下方。不得通过注入事件、改内部状态或请求建议接口代替网页操作。
2. 观察本次输入产生的新下拉框。输入法仍在组词、列表仍加载、建议仍属于旧词时继续正常观察；只在新列表至少两次观察一致后确认。不能仅凭固定等待时间判定成功。与上一查询完全相同的列表要确认重新加载/重建的可见证据；无法确认时记 `error` 并保留说明。
3. 仅转录搜索框下当前输入触发的建议行。历史搜索、猜你想搜、热榜、广告、账号卡片、视频标题、AI问答入口、搜索按钮等另有含义，排除。联想中实际出现的无关词保留原文，用行业评分降分。不同词可以得到同一列表，也可能得到零条，不补足数量。
4. 对搜索框与整个采集列表截图。截图工具返回JPEG时保存为 `.jpg`，PNG保存为 `.png`；检查实际格式。下拉若超过视口，先采当前可见行，注明 `list_truncated: true`；如无点击的工具能滚动下拉，可分屏截图并用重叠行核对顺序。禁止缩小共享窗口或通过点击展开。
5. 按视觉自上而下记录 `rank`。多屏截图时，每条建议的 `screenshot` 填实际展示该行的截图路径；重叠行保留其原始位置。同一词在不同路径/位置都保留。保留词条实际大小写、空格与标点；AX把字形分隔为空格时用截图核对还原，不能一律删空格。不要把省略号后的文字自行补全。
6. 每个不同检索使用独立截图文件名，不覆盖其他检索的证据；重试同词也用新文件名，成功后更新原查询引用。记录截图相对路径、时间、实际URL、`observed_input`、状态和备注；输入前后URL相同才作为本模式成功结果。若意外进入结果页，当前词记 `error` 并暂停，不自动回退刷新继续。不把输入框的建议URL伪造成已访问的搜索结果URL。
7. 每完成一词原子写入JSON，写成功后才开始下一词。截图保存失败记 `error`，不能交付 `ok`。下拉未出现时，确认输入框已聚焦、输入值正确、正常等待结束且没有登录/验证阻断；仅满足这些条件才记 `empty`，附空状态截图和 `empty_confirmation`。加载是否完成无法判断则记 `error`。

## 两层队列与恢复

- 广度优先：先输入每个根词采一级建议，然后按一级词首次出现顺序去重查询，得到二级建议。第二层结果不加入新队列。
- 检索词按原文精确去重，保留大小写差异。根词同时是其他根词的一级词时复用根词记录。自身词仅保留该建议行，路径停止向自己递归。多个根词共享一级词时复用查询，导出保留全部路径。
- 默认最多200个不同检索词，每次最多10个可见建议词。限制当前批量，逐词进行；保持列表更新后再执行下一词。限额、等待和节奏控制用于减少无效操作，不构成免验证保证。
- 达到上限时记录剩余 `pending`；登录/验证码/频率限制出现时保存当前词为 `blocked`，整个批次停止。不得继续轮询其他词规避限制。单词普通观察以30秒为上限，允许在同一已核对输入框内最多重输2次；仍无法确认则 `error`。时间届满只用于停止等待，不能单独作为空结果依据。不刷新恢复。
- 恢复时跳过有截图的 `ok` / `empty`，优先重试用户已解除阻断的项，延续原队列。替换同一查询的检查点，不追加重复查询。人工重新运行需另建批次，不混淆采集时间。

## 默认原生输入流程与实测处理

- 原生Chrome窗口操作是本Skill在Codex中的默认采集路径；每次输入前确认前台仍为用户授权的抖音页。用户切换到其他页面或正在操作时暂停，不能继续发送全局按键。电脑操作能力不可用或无法确认目标窗口时保存检查点，说明缺少的能力；已有数据可继续离线评分和导出。
- macOS实测中，直接键入中英混合词出现过只剩英文，原生粘贴也出现过目标值不一致。输入后立即核对完整值；失败时排除该列表，不把错误输入的词补进本批次。粘贴是可选输入方式，需逐次验证。
- 已验证的无鼠标编辑顺序：新状态中定位输入框 → `setValue` 填入完整词 → 再读状态核对完整值并重新定位 → `selectText` 将光标置于该词末尾（`cursor_after`）→ 原生 `pressKey('space')` 和 `pressKey('BackSpace')` → 读取状态。最终输入值、新列表及后续截图必须一致。该方式同样遵守重输次数和观察时限，工具不支持时记 `error`。
- 上述编辑会短暂形成带末尾空格的中间输入，仅采最终完整词对应的稳定列表。保持原文中的实际空格；禁止以删除词条空格来替代输入核对。全程仍可能产生联想请求。

## 实网页验证范围

2026-10-01在用户已登录的macOS Chrome `/jingxuan` 页面完成“GEO公司”的一根两层实采：11次不同查询、110条路径记录、80个原文精确去重词、11张原始JPEG截图。循环未鼠标点击、提交搜索或刷新；记录的页面URL保持一致。浏览器标签页连接失败，原生窗口方式可完成采集；完整输入核对拦截并纠正了输入异常。见 [实测报告](../reports/live-test-2026-10-01.md)。该证据覆盖这一会话，其他系统、未来页面和大批量连续运行仍需按实际状态验证。
